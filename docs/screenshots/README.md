# Screenshot checklist

The main README references these files by exact name. Drop each screenshot into this folder (`docs/screenshots/`) with the exact filename below and they'll render automatically on GitHub — no other changes needed.

PNG or JPG both work; keep the extension consistent with what's listed (rename on your end if you'd rather use `.jpg`, then update the one line in `../../README.md` that references it).

| Filename | What to capture |
|---|---|
| `landing.png` | The public landing page (logged out), full hero section |
| `auth.png` | The login/signup screen — either mode, whichever looks cleaner |
| `dashboard.png` | "My Resumes" dashboard after logging in, with at least one resume card visible |
| `builder.png` | The resume builder screen — form on the left, live preview on the right, mid-fill with real-looking sample content (not empty fields) |
| `templates.png` | The template picker `<select>` open, or one non-Classic template's live preview (Modern or Harvard show off the visual variety best) |
| `analyze.png` | The "Analyze against a job" results screen — score ring + matched/missing keywords + suggestions all visible |
| `ats-score.png` | The independent ATS Score results screen |
| `admin.png` | The admin panel — stats dashboard + user table both visible if it fits, otherwise the stats panel |
| `bg-removal.png` | The Contact section's background-removal panel, ideally mid-flow showing the color swatch picker |

Nice to have, not required — the README works fine without these two:

| Filename | What to capture |
|---|---|
| `admin-detail.png` | The per-user detail modal opened from the admin panel |
| `usage.png` | The self-service Usage screen (quota bar, recent activity) |

Use real-looking sample data where you can (a filled-out name/experience, not "asdf asdf") — screenshots with placeholder junk text read as unfinished even when the feature works fine.
